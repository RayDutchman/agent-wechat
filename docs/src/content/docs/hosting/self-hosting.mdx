## Recommended setup

The simplest production setup is a VPS with Docker:

1. **Provision a VPS** — any provider (AWS EC2, DigitalOcean, Hetzner, etc.) with at least 2 GB RAM and 10 GB disk
2. **Install Docker** — follow [Docker's official docs](https://docs.docker.com/engine/install/)
3. **Deploy with Docker Compose** — see [Docker Compose setup](/getting-started/container-setup/docker-compose)

## Security considerations

- The auth token secures the API. Keep it secret and use HTTPS if exposing the port externally.
- The container runs with elevated privileges (`SYS_PTRACE`, `seccomp=unconfined`). Run it on a dedicated VM or isolated Docker host.
- Use HTTPS if exposing port 6174 externally. Both the API and VNC viewer at `/vnc/` require the auth token.

## Monitoring

Check whether the container is running and whether the API reports server/login status (Compose does not define a Docker healthcheck):

```bash
# Container status
docker ps | grep agent-wechat

# Server and login status
wx status

# Container logs
wx logs
# Or, from the directory containing the deployment configuration:
docker compose logs -f agent-wechat
```

## Backups

Back up the Docker volumes periodically:

```bash
# Back up WeChat data
docker run --rm -v agent-wechat-home:/data -v $(pwd):/backup ubuntu tar czf /backup/wechat-home-backup.tar.gz -C /data .

# Back up agent data
docker run --rm -v agent-wechat-data:/data -v $(pwd):/backup ubuntu tar czf /backup/agent-data-backup.tar.gz -C /data .
```

## Updates

The canonical Compose configuration never pulls images. Verify and make the desired immutable image available locally, update `AGENT_WECHAT_IMAGE` in the deployment environment, then recreate during a maintenance window:

```bash
docker compose --env-file deployment.env config
docker compose --env-file deployment.env up -d
```

For CLI-managed deployments, use the CLI's documented update workflow instead:

```bash
wx up
```

After updating, the WeChat session usually persists. Scan the QR code in WeChat if prompted.
