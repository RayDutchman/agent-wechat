title: Tokens & Authentication
description: How auth tokens work, where to find them, and how to rotate them.
---

agent-wechat uses a simple token-based authentication to secure the REST API.

## Where the token lives

| Location | Description |
|----------|-------------|
| `~/.config/agent-wechat/token` | File on your host machine. Auto-generated on first `wx up`. |
| `/data/auth-token` | Inside the container (read-only mount of the host file) |
| `AGENT_WECHAT_TOKEN` env var | Overrides the file-based token |

## How the token is used

The token serves two purposes:

1. **API authentication** — every API request must include it in the `Authorization` header:
   ```
   Authorization: Bearer <token>
   ```
2. **Database encryption** — the same token is the SQLCipher key for `agent.db`, which stores sessions and agent metadata.

`wx` uses the local token file by default. Other clients must be configured with the token and server URL.

:::caution
Replacing or losing the token prevents the existing `agent.db` from being decrypted. Token regeneration does not re-encrypt that database. Preserve the matching token and database together; do not regenerate a token merely to troubleshoot a connection.
:::

## Generating a token manually

```bash
mkdir -p ~/.config/agent-wechat
openssl rand -hex 32 > ~/.config/agent-wechat/token
chmod 600 ~/.config/agent-wechat/token
```

## Regenerating the token

Using the CLI:

```bash
wx auth token --regenerate
```

Use regeneration only for an intentional credential reset with a corresponding database migration or reinitialization plan. Restarting with a different token alone will not unlock the existing database.

Or manually:

```bash
openssl rand -hex 32 > ~/.config/agent-wechat/token
```

Then restart the container so it picks up the new token:

```bash
wx down && wx up
# or
docker compose restart agent-wechat
```

## Remote access

When connecting a custom client to an agent-wechat server, provide its URL and token:

```bash
cat ~/.config/agent-wechat/token
```

For the CLI, set `AGENT_WECHAT_URL` and `AGENT_WECHAT_TOKEN`. Other clients should send `Authorization: Bearer <token>`; see the [REST API reference](/reference/api).
