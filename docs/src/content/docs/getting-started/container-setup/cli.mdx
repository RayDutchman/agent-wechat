---
title: Using the CLI (wx up)
description: Start agent-wechat with a single command.
---

Build this fork's CLI from source; the identically named npm package is published upstream and is not this fork's build. See the [quick start](/getting-started/quickstart). `wx up` may use a default image that does not contain this fork's server. Select a compatible image explicitly, for example through Docker Compose.

## Run CLI commands

After building the CLI, run API commands as `node packages/cli/dist/cli.js <command> ...` against the running server. Use the [Compose deployment guide](/getting-started/container-setup/docker-compose) to pull `ghcr.io/raydutchman/agent-wechat:2026.10.21` and start the service. That image supports interactive noVNC; builds using the source entrypoint retain its read-only default.

## With a proxy

When using the CLI's container helper, proxy options are available:

```bash
# HTTP proxy
wx up --proxy user:pass@host:port

# SOCKS5 proxy
wx up --proxy socks5://user:pass@host:port
```

This sets up a transparent proxy (redsocks + iptables) inside the container — invisible to WeChat.

## Stop the container

```bash
docker compose --env-file deployment.env stop
```

Use Compose explicitly to stop the service when that is how it was started. This retains the container and volumes.

### Use an existing local Compose project

To make `wx up` and `wx down` operate on a locally built image and an existing Compose project, create `~/.config/agent-wechat/container.json` with absolute paths:

```json
{
  "project": "agent-wechat-environment",
  "files": ["/absolute/path/to/compose.yml"],
  "env_file": "/absolute/path/to/.env"
}
```

With this file present, `wx up` runs `docker compose ... up -d`, and `wx down` runs `docker compose ... stop`. The config must be valid; it will not fall back to the default image if invalid. `--proxy` is not supported with this config; configure proxy settings in the Compose environment instead.

## Image selection

Choose an image compatible with this fork and your host architecture, or build it locally with the WeChat `.deb` you intend to run. The Dockerfile's mutable fallback does not pin a WeChat version. See [Docker Compose](/getting-started/container-setup/docker-compose) to select the image and persistent data explicitly.
