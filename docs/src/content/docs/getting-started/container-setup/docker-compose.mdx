The published `ghcr.io/raydutchman/agent-wechat:2026.10.22` image remains available for Linux AMD64 and ARM64. Both platforms passed isolated startup smoke checks only; this does not establish login or account-data behavior. The tested AMD64 image contains WeChat 4.1.13.26 and its older helper produced `keys_unavailable`, so it is not recommended for full account use. This published image has not been replaced by the fixed-package candidate. Pull explicitly before starting Compose, which does not pull automatically.

## Fixed WeChat package source builds

The fixed package is WeChat 4.1.13.23 AMD64, verified by `docker/verify-wechat-package.sh` against SHA-256 `b7d0f8d53e9f648bc2c77a6096a04100d008f2d9f0d3988a2a4859b5992aca0a`. Place the exact `.deb` at `docker/wechat.deb` by either setting `WECHAT_DEB_PATH` to a local package (the build runs `bash scripts/download-wechat.sh` to validate and stage it), or setting CI variable `WECHAT_DEB_AMD64_URL` to an archive location. The URL only locates the archive; it is not a trust check—the package is still verified against the pinned checksum and metadata. Missing packages, invalid packages, and unsupported architectures fail the build; there is no fallback download of the latest package. ARM64 source builds currently fail because no verified 4.1.13.23 archive is available. The fixed-package build is a candidate and has not yet been released.

```bash
WECHAT_DEB_PATH=/path/to/wechat_4.1.13.23_amd64.deb pnpm build:image:amd64
```

```bash
docker pull ghcr.io/raydutchman/agent-wechat:2026.10.22
```

The repository root `docker-compose.yml` is the canonical host-network deployment. It requires a verified local image, existing external data/home volumes, and an existing token file. For a new standalone deployment, create those resources first; never regenerate the token when reusing existing account data.

## 1. Prepare deployment settings

```dotenv
AGENT_WECHAT_IMAGE=ghcr.io/raydutchman/agent-wechat:2026.10.22
AGENT_WECHAT_TOKEN_FILE=/absolute/path/to/token
AGENT_WECHAT_DATA_VOLUME=agent-wechat-data
AGENT_WECHAT_HOME_VOLUME=agent-wechat-home
WECHAT_NATIVE_MEDIA_DOWNLOAD=false
```

With the updated repository Compose file, `WECHAT_NATIVE_MEDIA_DOWNLOAD=false` is passed directly into the container; no additional override file is needed. It disables native download requests while keeping local media cache reads available. Set it to `true` to enable native downloads; omitted or empty values retain the default `true`. Use an image supporting this switch (`2026.10.22` or later). Changing the env file alone does not update an already-running container; apply it during your next planned container recreation. Host environment variables override `deployment.env`, so confirm the rendered value before starting.

For a genuinely new deployment only, create the token once with restrictive permissions and create the external Docker volumes before starting Compose. For an existing installation, use its original token path and volume names; never regenerate or overwrite its token.

```bash
mkdir -p ~/.config/agent-wechat
openssl rand -hex 32 > ~/.config/agent-wechat/token
chmod 600 ~/.config/agent-wechat/token
docker volume create agent-wechat-data
docker volume create agent-wechat-home
```

Keep `deployment.env` private and do not commit credentials or token contents.

## 2. Validate and start

```bash
docker compose --env-file deployment.env config
docker compose --env-file deployment.env up -d
```

Stop with `docker compose --env-file deployment.env stop`; this retains the container and volumes. The provided image supports interactive noVNC through the authenticated API proxy; builds using the source entrypoint retain its read-only default. Non-container clients connect to the Docker host's reachable address on port `6174`, not the service name.

## Key configuration

### Security options (required)

- `seccomp=unconfined` — allows all syscalls (ptrace needs this)
- `SYS_PTRACE` — required to interact with the WeChat desktop process

These are **not optional**. Without them, the server cannot control WeChat. See [Hosting Requirements](/hosting/requirements) for details.

### Volumes

| Volume | Path in container | Purpose |
|--------|-------------------|---------|
| `agent-wechat-data` | `/data` | Agent database, auth token |
| `agent-wechat-home` | `/home/wechat` | WeChat user data, databases, media files |
| Token file | `/data/auth-token` | Read-only auth token mount |

### Networking with a custom client

Host networking binds the API on `[::]:6174` and has no Compose port mapping. Non-container clients must connect using the Docker host's actual reachable address, such as `http://192.0.2.10:6174`, not the Docker service name. Provide the API token in authenticated requests.


### Proxy

The canonical Compose file does not configure `PROXY`. Configure proxy routing through the supported `wx up --proxy ...` workflow or a separately reviewed deployment customization; `NET_ADMIN` is retained in Compose for compatibility with the container's networking requirements.
