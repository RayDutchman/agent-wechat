The server exposes an HTTP API on port `6174`. This page describes the current router in `packages/agent-server-rust/src/router/mod.rs`, with V2 handlers in `router/read_v2.rs` and `router/send_v2.rs`. A registered route does not by itself prove useful events or message delivery.

数据库字段原义、表间关联、通讯录筛选、消息类型及 `server_id` / `local_id` 的统一解释见 [微信数据库与字段字典](/operations/data)。本页维护 HTTP 契约，不另维护一套源数据库语义。

## Authentication

```text
Authorization: Bearer <token>
```

The middleware also accepts `?token=...` for browser WebSockets. Missing or incorrect credentials return 401 with `{"error":"Unauthorized"}`. `/health` and noVNC static resources are exempt; `/vnc/websockify` is authenticated. There is no `/api/auth` token-issuing endpoint.

## Current HTTP surface

Decoded uploads are limited to 128 MiB; the global body allowance includes base64 expansion plus JSON overhead. Extractor, authentication and body-limit failures can occur outside a handler's result envelope.

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | Process health only; not WeChat readiness. |
| GET | `/api/v2/account` | Fresh account/UI observation; unknown observations remain explicit. |
| POST | `/api/status/login` | Read current QR state; does not initiate login. |
| POST | `/api/status/logout` | Execute logout and clear persisted login identity. |
| POST | `/api/chats/{id}/open` | GUI selection; optional `clearUnreads=false`; returns `ok,username?,index?,error?`, including 200 with `ok:false`. Official accounts are unsupported. |
| GET | `/api/v2/contacts`, `/api/v2/chats` | Cursor-paged roster reads. |
| GET | `/api/v2/chats/{username}`, `/api/v2/chats/{username}/members` | Exact chat and group-member reads. |
| DELETE | `/api/v2/read-snapshots/{release_token}` | Release a frozen sample. |
| GET | `/api/v2/chats/{username}/messages` | Cursor-paged messages. |
| GET | `/api/v2/messages/{server_id}` | Exact native message lookup. |
| GET | `/api/v2/messages/{server_id}/media`, `/api/v2/messages/{server_id}/voice` | Media result or raw SILK bytes. |
| GET | `/api/v2/message-types` | Canonical type dictionary. |
| POST | `/api/v2/messages/send` | One synchronous send; file > image > text. |
| POST | `/api/messages/voice` | Create an asynchronous voice job. |
| GET | `/api/messages/voice/{job_id}` | Read voice job status. |
| POST | `/api/messages/voice/{job_id}/cancel` | Request cancellation. |
| GET / POST | `/api/sessions` | List/create sessions. |
| GET / DELETE | `/api/sessions/{id}` | Read/delete a session. |
| POST | `/api/sessions/{id}/start`, `/api/sessions/{id}/stop` | Start/stop a session. |
| GET | `/api/debug/screenshot`, `/api/debug/a11y` | UI diagnostics. |
| GET | `/api/ws/login`, `/api/ws/events` | WebSocket upgrades described below. |
| GET | `/vnc/websockify`, `/vnc/{*path}`, `/vnc/` | Authenticated VNC transport and static viewer. |

Retired routes return 404: `/api/status`, `/api/status/auth`, `/api/read/*`, `/api/messages/{chat_id}` and its local-ID media route, `/api/messages/send`, `/api/send/text`, `/api/send/file`, and legacy chat/contact list/find/get routes. There is no compatibility fallback. The retained `<chat> <localId>` CLI media syntax resolves a unique V2 message to a nonzero `server_id` and releases its page sample before requesting media.

## V2 reads

List responses are `{items,next_cursor,release_token}`. Nullable fields are explicit `null`. Initial reads can express account intent with `expected_account_username`; callers do not supply epochs, account directories or shard names.

| Resource | Parameters and result |
|---|---|
| Contacts | Optional `q`, `kind`, `limit=100`, `cursor`; `offset` rejected. |
| Chats | Optional `q`, `limit=100`, `cursor`; `offset` rejected. |
| Exact chat | Source `username`; returns `ChatV2`, or 404 `not_found`. |
| Group members | Optional `limit=100`, `cursor`; missing room is 404. Local empty records do not establish actual membership. |
| Chat messages | `limit=100`, `cursor`, `order=desc|asc`, optional URL-encoded JSON `include`/`exclude`; `offset` rejected. |
| Native message | Canonical nonzero signed-i64 decimal `server_id`; optional `chat_username` narrows lookup. Invalid ID/query is 400, missing message 404, ambiguous match 409. |
| Media | Same locator, plus `quality=best|legacy|full|standard|thumbnail`; returns `MediaResult`, including `pending` or `unsupported`. |
| Raw voice | Same locator; returns raw SILK bytes (`audio/silk`), not the retired base64 envelope. Missing local voice source is 503 `voice_source_missing`. |
| Snapshot release | Opaque `release_token`; returns `{released:boolean}`. Removes frozen cache data, never source messages; identity checks and the GUI guard still apply. |

`conversation_username` is rejected rather than aliased. `MessageV2.chat_username` is the containing chat identity; nullable `ReferenceV2.chat_username` is the reference's chat identity. Native lookup scans only validated `Msg_<32 lowercase hex>` tables in the current account, binds the ID as a SQL parameter and refuses multiple matches. Media and voice use the resolved source anchor. Raw voice bytes are bounded at 32 MiB; invalid SILK data, ambiguous media sources and source changes fail rather than return unrelated bytes.

### Pagination and budgets

Continue on the same endpoint with the opaque `cursor`. Only `next_cursor: null` is terminal, not a short page. Cursor-only requests inherit filters and order; explicitly changing `q`, `kind`, `order`, `include` or `exclude`, or changing the resource/room scope, is rejected with 409. The server does not recollect or broaden a continuation.

The limit is 1–1000 (default 100), with a 3 MiB serialized-items page ceiling. Frozen samples have an absolute 300-second TTL, four retained-sample slots, 50,000 rows/16 MiB per sample, and 32 MiB total serialized row data. Capacity exhaustion rejects new samples with 413 rather than evicting unexpired cursors. Single-page results have `release_token: null`; otherwise the token remains stable across the sample. Release after completion or abandonment. If release fails, keep successful read results and let TTL reclaim the sample; do not replay business actions.

Repeated cursors return the same frozen rows until release/expiry. Account/process/session scope changes can invalidate them; server restart loses the in-memory cache. A frozen sample is local coverage, not complete remote history or a simultaneous cross-database transaction.

Read errors use `{error,code}`:

| HTTP | Codes |
|---|---|
| 400 | `invalid_parameter` |
| 404 | `not_found` |
| 409 | `scope_changed`, `ambiguous` |
| 410 | `expired` |
| 413 | `budget_exceeded` |
| 500 | `source_read_failed` |
| 503 | `identity_unavailable`, `keys_unavailable`, `source_unavailable`, `voice_source_missing` |
| 504 | `deadline_exceeded` |

Read rounds have an 8-second budget, including at most 2 seconds waiting for the GUI guard; collection interrupts SQL and caps decompressed content at 4 MiB per row. Missing required keys, unreadable shards and invalid rows fail the request instead of producing successful partial data. Media transfer waiting has its own policy below.

### Source isolation and identity

The reader copies the source database and WAL as ordinary file bytes, merges the valid committed prefix, and opens only a private encrypted copy with SQLite. It does not open the live source with SQLite, checkpoint or rewrite it, and needs no source `-shm`. Source rowids, including implicit rowids, are preserved. Invalid WAL headers fail; frame validation stops at the first invalid frame, merging only preceding valid commits. No valid committed frames does not prove there are no newer messages.

A 512 MiB per-build processing budget covers the source database, WAL, merge index and merged copy; it is not a process-wide memory limit. A source that changes during copying is refused. SQLCipher HMACs are checked as pages are read, not for every logical page up front. Unchanged file metadata and keys permit reuse of a private copy, with independent SQLite connections. This four-entry copy cache is separate from frozen pagination. Graceful shutdown clears retained copies; abrupt termination can leave private files.

Identity checks remain internal. Successful recorded login/logout writes advance a generation; process, boot, session or account-root changes also affect scope. Failed login writes block trusted identity reads until a successful write. Ordinary polling does not advance the generation. An epoch is not continuous proof of every external UI login transition. Account observation uses current UI evidence; persisted identity alone is not proof of login. Voice jobs use their separate account ownership rules below.

### Message fields and filters

`ChatV2.username` is the source identity. `last_msg_sender` and `last_sender_display_name` preserve source session sender values, normalizing empty strings to `null`. `unread_count` preserves SQL NULL as JSON `null` and otherwise retains source integers.

Filters use `include=[{"type":49,"sub_type":6}]` and `exclude=[{"type":10000}]` as URL-encoded JSON arrays. Omitted `include` means all types; `include=[]` means none. Entries within a list are ORed, the two dimensions are ANDed, and exclusion wins. A sub-type requires a type. Unknown non-negative u32 codes are accepted and preserved. CLI `--config` accepts only `include` and `exclude` arrays.

The canonical dictionary is `packages/agent-server-rust/src/message-type-dictionary.json`, also generated into the shared/CLI module. Namespaces `main`, `appmsg` and `forwarded_inner` are separate; each entry has numeric `code`, English `key`, Chinese `label`, and `basis` (`default_adopted` or `local_observed`). Unknown codes remain numeric, not coerced to text.

`MessageV2.server_id`, `local_id` and `raw_type` are decimal strings (zero/missing message IDs are `null`); `type` and `sub_type` are the low/high u32 portions of the stored i64 bit pattern. `timestamp` comes from `create_time`: missing/non-integer values fail frozen collection; out-of-range integers follow the collector's empty timestamp path and become `null` in V2.

`raw_content` is opaque retained hex, not decoded XML. Required `raw_content_compression` is the source boolean flag and must accompany those bytes. `content` retains clean/display behavior. Independently decoded `xml_sub_type` may differ from packed `sub_type`; neither rewrites the other. `reference` preserves `svrid` as source text (including `"0"`), chat identity, `chatusr` and `displayname` separately. Group `fromusr` supplies the reference chat; direct chats use current chat context. Missing `chatusr` remains missing; no author is inferred from display names or `fromusr`.

For app-message subtype 19, `forwarded_record.items` preserves order, `datatype`, `dataid`, `datadesc`, source display fields and lexical time/message-ID strings. `dataitem_source_hash_username` is a hash, not an addressable username. `parse_status` is `complete`, `truncated` or `invalid`; truncation retains a complete prefix, malformed XML returns no items. Limits: 4 MiB decoded XML, depth 16, 20,000 nodes/events, 100 entries and 64 KiB per description. DTD/entity declarations are rejected; external resources are not resolved. Unfamiliar shapes may be invalid. No nested messages are scheduled or URLs fetched; these fields do not alter content, media or sends. CLI JSON keeps the snake_case V2 fields and readable output distinguishes inner and outer types.

## Synchronous sending

`POST /api/v2/messages/send` accepts nonempty `chat_username`, optional `expected_account_username`, and these payload fields:

- `text`: nonempty string.
- `image`: `{data,mime_type}` with base64 data and `image/png`, `image/jpeg`, `image/gif` or `image/webp`.
- `file`: `{filename,data,sha256,size}` with a single basename, base64 data, lowercase SHA-256 and decoded byte count.

Unknown fields are rejected. One payload is selected by **file > image > text**; other supplied fields are reported in `ignored_fields`. Supplied JSON shapes must be valid, but only selected bytes are decoded/verified. An invalid selected payload never falls back to another field. Files must match the declared digest/size and 128 MiB decoded limit; filenames reject separators, control bytes, `.` and `..`.

The result reports `success`, `account_username`, `chat_username`, `selected_payload`, `ignored_fields`, `commit_attempted`, `ui_confirmed`, `error_code` and `failure_stage`; file results also report accepted `payload_sha256` and `payload_size`. Preflight errors use non-success HTTP statuses; execution refusals can return HTTP 200 with failure fields. Authentication, malformed JSON and outer body-limit errors need not use this envelope.

Sending holds the shared GUI guard, verifies account and selected destination, and rechecks them before Return. Uploads are staged privately with preserved basenames and the trusted session user's ownership. File/image preparation requires an empty composer, successful bounded paste and a fresh readiness observation before committing. Occupied input is refused, not cleared. The UTF-8 launcher/paste helper preserves staged filenames; a helper exit is not delivery proof.

Preserve commit facts even on errors. `ui_confirmed` does not prove recipient delivery; reconcile newly observed outgoing messages against a pre-send baseline. Do not automatically repeat a timed-out or uncertain send. This synchronous endpoint has no idempotency key. Outgoing voice uses the separate job API.

## Media quality

For image media, `quality=full` requires the original copy, `standard` requires the mid-size copy, and `thumbnail` requests the preview. Omitted quality defaults to `best`: return the best valid local copy, requesting native full-size transfer only when the message advertises an Original. With `WECHAT_NATIVE_MEDIA_DOWNLOAD=false`, the endpoint uses only local copies and does not submit native requests or wait; the response `quality` labels `full`, `standard` or `thumbnail` when bytes are available.

When native downloads are enabled, the server waits up to 20 seconds before returning the best cached fallback. A `pending` response in this mode can indicate that native media is unavailable; it does not guarantee a request was queued.

A regular phone send may advertise only a standard image. Opening its chat separately can make WeChat cache it; the media endpoint never selects a chat. Without that copy, `best` can return a thumbnail while strict `standard` has no image bytes. Pending results require bounded retries; disconnecting HTTP does not cancel an already submitted server-owned transfer. Raw message XML is not a retrieved attachment.

## Sessions and diagnostics

Session creation takes JSON `name`, allocates display/port and invokes `useradd -m`. Session lookup accepts ID or name and returns a session or `null`. Starting launches display, D-Bus, accessibility, VNC and WeChat; stopping terminates session-user processes and cleans X locks. Deleting a session additionally removes records and runs `userdel -r`: it is destructive. Handler refusals can use a 200 response containing `error`; sessions are not substitutes for `/api/v2/account` observations.

`/api/debug/screenshot` returns `base64` (possibly empty on failure). `/api/debug/a11y?format=json|aria` returns `tree` or `aria`, or a 200 response with `error`.

## Voice jobs

Create with multipart `chatId` and `audio`, plus `Idempotency-Key` (1–200 characters, no controls). A new job returns 202; the same account/key/payload replays status with 200. Reusing the key for different destination/audio returns 409; malformed fields return 400, empty/oversized audio 413, storage failure 500, and not logged in 409.

Status includes `jobId,chatId,accountId,status,sourceDurationSeconds,chunks,error`. Preserve per-chunk results and `needs_review`. Status lookup requires a UUID; invalid, missing, unreadable or another account's job returns 404. Cancel returns 202 with current status, not proof cancellation finished; terminal jobs return 409. Previously sent chunks are not recalled.

Before recording, the worker takes the shared GUI guard, compares the persisted logged-in account, selects the destination and checks its returned native identifier. Ownership uses the persisted current account, not the synchronous sender's epoch fence. A restart marks interrupted work failed or `needs_review` rather than resending it. See `router/voice.rs` for the job contract.

## WebSockets and VNC

All three upgrades require authentication; browser clients may use the `token` query parameter.

| Path | Parameters and behavior |
|---|---|
| `/api/ws/login` | `timeoutMs=300000`, `newAccount=false`. Starts `LoginPlan` under the GUI guard; emits status, QR, phone-confirm, success, timeout/error events. Disconnect/timeout cancels execution. This is active login with identity writes and possible key extraction, not a passive subscription. |
| `/api/ws/events` | Emits only `{"type":"data_changed"}`. Watches message `.db`/`.db-wal` changes, excludes `.db-shm`, and coalesces from the first change in a bounded 300 ms window. No message identity/body, cursor, acknowledgement or replay. The watcher does not query message SQL. |
| `/vnc/websockify` | Bidirectional authenticated proxy to local websockify; supports `binary` subprotocol. Upstream connection failure ends the handler. |

Treat `data_changed` as an invalidation hint: catch up at startup and after reconnect. Shared `subscribeChanges` only yields events; it does not read messages. There is no registered SSE `/api/events/subscribe` endpoint.

`/vnc/` serves a token prompt or viewer HTML (`autoconnect=true|1`); the static route does not validate the token itself. `/vnc/{*path}` serves assets, rejects `..` with 403 and returns 404 for missing files. Input permissions are controlled by the VNC backend, not the proxy; see [VNC Viewer](/operations/vnc) for deployment-specific access.
