## CLI and custom clients

| Variable | Default | Description |
|----------|---------|-------------|
| `AGENT_WECHAT_URL` | `http://localhost:6174` | Server URL |
| `AGENT_WECHAT_TOKEN` | — | Auth token (overrides the token file at `~/.config/agent-wechat/token`) |

## Server-side (inside the container)

| Variable | Default | Description |
|----------|---------|-------------|
| `AGENT_DB_PATH` | `/data/agent.db` | Path to the agent SQLite database |
| `PROXY` | — | Transparent proxy address (format: `user:pass@host:port` or `socks5://...`) |
| `DISPLAY` | `:99` | X11 display (set automatically by the container entrypoint) |
| `DBUS_SESSION_BUS_ADDRESS` | — | D-Bus session bus address (set automatically) |
| `WECHAT_NATIVE_MEDIA_DOWNLOAD` | `true` | Enable the server-owned native media download worker. Only exact `true` or `false` values are accepted; any other value disables native requests. Local media cache reads remain available. |

## Desktop environment

These settings apply to the default desktop and desktops newly started through the session API. Changes take effect after restarting the corresponding desktop process; running `export` in an already-running container does not change the existing WeChat process.

| Variable | Default | Description |
| --- | --- | --- |
| `WECHAT_SCREEN_WIDTH` | `1280` | Xvfb screen width in positive integer pixels |
| `WECHAT_SCREEN_HEIGHT` | `800` | Xvfb screen height in positive integer pixels |
| `WECHAT_SCREEN_DEPTH` | `24` | Xvfb screen depth; accepts `8`, `16`, or `24`. Application configuration has only been verified at the default `24`. |
| `WECHAT_SCREEN_DPI` | `100` | Xvfb display DPI as a positive integer |
| `WECHAT_LOCALE` | `C.UTF-8` | Set as `LANG`, `LC_ALL`, and `LC_CTYPE` when WeChat starts |
| `TZ` | `UTC` | Process time zone; the selected zone must have zoneinfo available in the image |
| `ENABLE_VNC` | `1` | Whether to start read-only VNC and websockify for the default desktop; set to `0` to disable automatic startup |

Chinese file paths have been verified in a UTF-8 environment; do not assume their behavior remains unchanged if the locale is set to `C` or `POSIX`. Resolution or DPI changes can affect the client's layout and control locations, so check the actual interface in an isolated environment. Audio device names and 48 kHz mono settings remain fixed by the current implementation; audio configuration is not exposed here.

Unset or empty values use the defaults. Nonempty invalid values are rejected before startup rather than silently replaced. The locale must be installed; `C.UTF-8` may be normalized to the equivalent `C.utf8` listed by the image. Language packs are not installed automatically. Numeric parameters must be positive decimal `u32` values without leading zeros; being within that format's range does not guarantee the screen dimensions can be allocated, and resource limits can still cause startup to fail.

The health monitor's timeout for an unrecognized interface is currently 120 seconds and uses the existing detection and restart logic. This is a code constant, not an environment variable. A longer wait does not resolve the cause of a collection failure or unknown interface.

### Dockerfile, startup scripts, and Compose responsibilities

- **Dockerfile**: Selects the base distribution, system dependencies, fonts, and WeChat package, and provides environment-variable defaults.
- **Startup scripts and session manager**: Pass environment variables to Xvfb and WeChat; adding an arbitrary Docker environment variable does not make it take effect automatically.
- **Compose / `docker run`**: Selects the image, hostname, network, volumes, token mount, and resource settings. Do not bake account data or tokens into the image.
- **Host**: Provides the kernel and actual CPU capabilities. A container CPU quota does not change the CPU model, and the distribution selected by `FROM` is not a separate running kernel.

### Host-network Compose deployment

The repository-root `docker-compose.yml` is the only Compose configuration. It uses host networking and does not set `ports`. Clients outside the container must connect to an address reachable on the Docker host (for example, `http://<host-address>:6174`); do not assume the Docker service name `agent-wechat` is reachable through a container network.

Store machine-specific configuration outside the repository, for example in `deployment.env`:

```dotenv
AGENT_WECHAT_IMAGE=sha256:replace-with-verified-image-id
AGENT_WECHAT_TOKEN_FILE=/absolute/path/to/existing/token
AGENT_WECHAT_DATA_VOLUME=agent-wechat-data
AGENT_WECHAT_HOME_VOLUME=agent-wechat-home
AGENT_WECHAT_HOSTNAME=agent-wechat
WECHAT_SCREEN_WIDTH=1280
WECHAT_SCREEN_HEIGHT=800
WECHAT_SCREEN_DEPTH=24
WECHAT_SCREEN_DPI=100
WECHAT_LOCALE=C.UTF-8
TZ=UTC
ENABLE_VNC=1
WECHAT_NATIVE_MEDIA_DOWNLOAD=false
```

The Compose file passes `WECHAT_NATIVE_MEDIA_DOWNLOAD` from `deployment.env` into the container; no override file is needed. The example disables native downloads while retaining local cache reads. Set `true` to enable native downloads. If omitted or empty, Compose uses `true` for backward compatibility. Host environment variables take precedence over values in `--env-file`, so inspect the rendered configuration below. This setting requires an image with the media switch, such as release `2026.10.22` or later.

Replace the example with a locally verified image ID or immutable digest; Compose does not pull images automatically. Data volumes must be existing external volumes. Use the existing token file: do not regenerate it when taking over existing data, or current client credentials will stop working. A missing token path is not automatically created as a directory. For a new, independent deployment only, prepare volumes and a token as described below. The configuration fixes host networking, API listener `[::]:6174`, existing capabilities/seccomp settings, 64 MiB shared memory, and screen/locale/TZ/VNC settings.

```bash
# Render and inspect the configuration without starting or replacing a container.
docker compose --env-file /path/to/deployment.env config
```

Taking over an existing container involves stopping the service and recreating the container, so do this during a maintenance window. Confirm the existing volume names, token, hostname, software version, and metadata; do not mistake a newly created project with the same name for an in-place update. Keep VNC in `-viewonly` mode. Port 5900 listens only on `127.0.0.1` and `::1`, and websockify on 6080 listens only on loopback; access it through the authenticated API proxy.

### Fixed WeChat package builds

Source image builds require the verified WeChat 4.1.13.23 package for AMD64 or ARM64. `docker/verify-wechat-package.sh` pins each architecture's SHA-256 and validates package metadata. Set `WECHAT_DEB_PATH` to an explicit local `.deb`; `bash scripts/download-wechat.sh` validates it and stages it as `docker/wechat.deb`. In CI, `WECHAT_DEB_AMD64_URL` and `WECHAT_DEB_ARM64_URL` specify archive locations; the URLs are not trust checks, and downloaded packages must pass the same verification. Missing or invalid packages and unsupported architectures fail; the build does not download the latest package as a fallback. The published `2026.10.29` dual-architecture image uses these fixed packages. Startup smoke checks do not validate login or account-data behavior.

## File paths (inside the container)

| Path | Description |
|------|-------------|
| `/data/auth-token` | Auth token file (read-only mount) |
| `/data/agent.db` | Agent SQLite database |
| `/home/wechat/` | WeChat user home directory |
| `/opt/agent-server/agent-server` | Agent server binary |
| `/opt/tools/` | Tool scripts (screenshot, click, input, etc.) |
| `/opt/novnc/` | noVNC web viewer |
