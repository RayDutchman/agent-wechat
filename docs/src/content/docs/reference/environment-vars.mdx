## CLI and custom clients

| Variable | Default | Description |
|----------|---------|-------------|
| `AGENT_WECHAT_URL` | `http://localhost:6174` | Server URL |
| `AGENT_WECHAT_TOKEN` | — | Auth token (overrides the token file at `~/.config/agent-wechat/token`) |

## Server-side (inside the container)

| Variable | Default | Description |
|----------|---------|-------------|
| `AGENT_DB_PATH` | `/data/agent.db` | Path to the agent SQLite database |
| `PROXY` | — | Transparent proxy address (format: `user:pass@host:port` or `socks5://...`) |
| `DISPLAY` | `:99` | X11 display (set automatically by the container entrypoint) |
| `DBUS_SESSION_BUS_ADDRESS` | — | D-Bus session bus address (set automatically) |

## 桌面环境配置

以下参数用于默认桌面和通过 session API 新启动的桌面。修改后需要重新启动对应桌面进程才生效；仅给已经运行的容器执行 `export` 不会改变现有微信进程。

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `WECHAT_SCREEN_WIDTH` | `1280` | Xvfb 屏幕宽度，正整数像素 |
| `WECHAT_SCREEN_HEIGHT` | `800` | Xvfb 屏幕高度，正整数像素 |
| `WECHAT_SCREEN_DEPTH` | `24` | Xvfb 屏幕色深，接受 `8`、`16`、`24`；只验证了默认 `24` 下的应用配置 |
| `WECHAT_SCREEN_DPI` | `100` | Xvfb 显示 DPI，正整数 |
| `WECHAT_LOCALE` | `C.UTF-8` | 微信启动时统一传给 `LANG`、`LC_ALL`、`LC_CTYPE` |
| `TZ` | `UTC` | 进程时区，所选时区需镜像内已有对应 zoneinfo |
| `ENABLE_VNC` | `1` | 默认桌面是否启动只读 VNC 与 websockify；设为 `0` 关闭自动启动 |

中文文件路径已在 UTF-8 环境验证；不要把 locale 改成 `C`/`POSIX` 后仍假定中文行为不变。改变分辨率/DPI也可能影响具体客户端的布局和控件定位，需要在隔离环境检查实际界面。音频设备名及 48 kHz 单声道参数保持现有实现，本轮未开放音频配置。

未设置或空值采用默认值；非空的非法参数在启动前拒绝，不静默改用另一组参数。locale 必须已安装，`C.UTF-8` 可规范化为镜像列出的等价 `C.utf8`；不自动安装语言包。数值参数为无前导零的正十进制 `u32`；该格式上限不是可分配屏幕尺寸的保证，超出实际资源仍会启动失败。

健康监控的界面不可识别超时现为 120 秒，仍沿用原有检测和重启逻辑；这是代码常量，不是本表新增的环境变量。延长等待不代表已解决采集失败或未知界面的原因。

### Dockerfile、启动脚本和 Compose 的分工

- **Dockerfile**：选择基础发行版、系统依赖、字体和微信安装包，并提供环境变量默认值。
- **启动脚本及 session manager**：将环境变量真正传给 Xvfb 和微信；不是任意新增一个 Docker 环境变量就会自动生效。
- **Compose / docker run**：选择镜像、主机名、网络、卷、token 挂载和资源配置。不把账号数据或 token 烘焙到镜像。
- **宿主机**：提供内核与真实 CPU 能力。容器 CPU 配额不等于修改 CPU 型号，`FROM` 选择的发行版也不是另一套运行内核。

### Host 网络 Compose 部署

仓库根目录的 `docker-compose.yml` 是唯一 Compose 配置，固定使用 host 网络，不设置 `ports`。非容器客户端必须连接运行 Docker 主机可达的真实地址（例如 `http://<host-address>:6174`），不能用 Docker 服务名 `agent-wechat` 假定容器网络可达。

在仓库外保存本机配置，例如 `deployment.env`：

```dotenv
AGENT_WECHAT_IMAGE=sha256:replace-with-verified-image-id
AGENT_WECHAT_TOKEN_FILE=/absolute/path/to/existing/token
AGENT_WECHAT_DATA_VOLUME=agent-wechat-data
AGENT_WECHAT_HOME_VOLUME=agent-wechat-home
AGENT_WECHAT_HOSTNAME=agent-wechat
WECHAT_SCREEN_WIDTH=1280
WECHAT_SCREEN_HEIGHT=800
WECHAT_SCREEN_DEPTH=24
WECHAT_SCREEN_DPI=100
WECHAT_LOCALE=C.UTF-8
TZ=UTC
ENABLE_VNC=1
```

将示例值替换为本机已验证的镜像 ID 或不可变 digest；Compose 禁止自动拉取。数据卷必须是已有外部卷。token 必须是原有 token 文件：不要为接管已有数据重新生成 token，否则现有客户端凭据将失效；缺失的 token 路径不会被自动创建成目录。仅全新独立部署时，先按下方首次部署说明准备卷和 token。配置固定 host 网络、API `[::]:6174`、原 capabilities/seccomp、64 MiB 共享内存及屏幕/locale/TZ/VNC 设置。

```bash
# 只展开并检查配置，不启动或替换容器。
docker compose --env-file /path/to/deployment.env config
```

实际接管已有容器会涉及停止业务及重建容器，须在维护窗口进行。核清原有卷名、token、hostname、程序版本和元数据，不把新建同名项目误当原容器就地更新。VNC 保持 `-viewonly`，5900 仅监听 `127.0.0.1` 和 `::1`，websockify 6080 仅回环，通过已认证的 API 代理访问。

### 客户端版本固定

完整源码镜像构建当前优先使用 `docker/wechat.deb`，缺包时仍有官方可变 URL 下载路径；后者不能保证重建时得到同一微信版本。需要重新安装固定版本时，应保存已验证的原始安装包及其校验值，不能仅凭镜像标签推断微信版本。

如果原安装包已不可得，可以从**已经验证且精确固定的运行镜像**派生配置更新镜像，保留其中的微信和系统依赖，仅替换已验收的 server/启动脚本。这是复用已有安装，不是从原始 deb 完整重建的证明。构建产物须在同一目标运行镜像检查 ABI 与实际启动；不要混入账号数据、临时调查文件或宿主构建的不兼容二进制。

## File paths (inside the container)

| Path | Description |
|------|-------------|
| `/data/auth-token` | Auth token file (read-only mount) |
| `/data/agent.db` | Agent SQLite database |
| `/home/wechat/` | WeChat user home directory |
| `/opt/agent-server/agent-server` | Agent server binary |
| `/opt/tools/` | Tool scripts (screenshot, click, input, etc.) |
| `/opt/novnc/` | noVNC web viewer |
