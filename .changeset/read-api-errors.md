Return explicit HTTP errors for unavailable sessions, missing login state or database keys, and database read failures in chat, contact and message reads; a successful empty result keeps its existing JSON shape, and errors omit private database details. Read committed WAL data, resolve numbered shards and filter contacts before pagination.

Add frozen, cursor-paged message and contact-roster reads with bounded byte-aware pages, replayable cursors and explicit release, plus a monotonic per-session login generation that does not require existing logins to repeat. Add an epoch-fenced `POST /api/send/text` that rechecks account and chat before Return, and an epoch-fenced single-file `POST /api/send/file` that verifies the uploaded bytes, stages them privately for the session login user, requires an empty composer, pastes under one GUI guard, and commits in a separate Return step. Add `GET /api/read/voice` for one stored voice note under the same fences. UI confirmation and an accepted upload are not delivery; reconcile outbound records and never auto-repeat an uncertain commit.

Report a stuck send with a stable reason instead of a generic failure: `chat_not_open` when the focus round did not observe an open chat and `chat_selection_failed` when the chat selection helper did not answer with success. The fenced endpoints report the reason as their `errorCode`, and the legacy send reports it in `error` unchanged; no action, phase, commit evidence or existing error text changes.

Read each WeChat database from an isolated byte snapshot instead of opening the live file: copy the database and its committed write-ahead log, merge the committed prefix, and query a private encrypted copy. The live database is no longer opened, locked or checkpointed by a read and needs no source `-shm`, so a writer's lock cannot block or fail a read; a source that changes during the copy fails with the existing source-changed code, and a malformed write-ahead log fails the read rather than silently falling back to older rows. The generic read path maps every snapshot failure to `WECHAT_DB_READ_FAILED`. Rowids are preserved exactly (including PK-less tables), so `WHERE rowid = ?1` lookups keep working. A source whose database, write-ahead log, merge index and merged image together exceed 256 MiB is refused with the existing budget code rather than read. Unlike the old host-side page decryptor, pages are authenticated as they are read, not all up front.

Redirect the backgrounded cleanup of a non-ASCII paste copy so it holds no inherited output stream: the fenced single-file send runs the paste helper with both output streams piped and reads them to end-of-file, so that cleanup's ten-second sleep kept the read open past the helper's own completion. Copying, naming, extension and the asynchronous cleanup timing are unchanged.
